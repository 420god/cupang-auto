## 한 일

등록 모달 한 판을 **10개 화면 파이프라인**으로 쪼갰다(D-21).

```
소싱 즐겨찾기 → [등록 준비]
  ① 카테고리(+카탈로그 매칭) → ② 상품명·검색어 → ③ 옵션·가격 → ④ 검색필터
  → ⑤ 대표이미지 → ⑥ 상세페이지 → ⑦ 물류·바코드 → 상품등록에서 확인 후 발사
                                        등록 설정(기본값·양식)
```

마이그레이션 **031~038** 8개, 웹 파일 **86~94** 9개 신설, 워커에 `itemCommon` 병합 추가.

## 틀린 것

1. **필수속성을 추측으로 채웠다.** 값을 담을 자리가 없어서 색상←옵션명, 무게←잰 값으로
   유추했는데, 실측에서 복제 원본의 `색상=감자색 · 개당 중량=70g`이 그대로 등록될 뻔했다.
   → 038로 자리를 만들자 추측이 사라졌다. **추측이 필요하다는 건 저장할 자리가 없다는 신호다.**
2. **카탈로그 매칭 파서가 `categoryId`(7359)를 등록 코드로 집었다.** 진짜는
   `displayCategoryInfo[0].leafCategoryCode`(103112). 그대로 뒀으면 엉뚱한 카테고리로 등록됐다.
3. **뼈대 완료 판정에 남긴 예외 하나가 규칙을 통째로 무력화했다**(035 → 036).
   `or 복제 원본 있음`을 뒀는데 뼈대를 붙일 때 복제 원본 ID도 같이 채워져서,
   한쪽만 붙여도 완료로 떴다.
4. **"결과 0건"과 "파싱 실패"를 같은 문구로 뭉갰다.** 사용자가 URL로 검색해 0건이 나왔는데
   화면은 "필드 이름이 예상과 다릅니다"라고 했다 — 사실이 아니었다(R-15 위반).
5. **URL을 그대로 API에 보냈다.** `keyword` 에는 상품번호만 넣어야 한다. WING 화면도
   URL 을 붙여넣으면 숫자만 뽑아 보낸다 — 첫 캡처에 이미 답이 있었는데 못 봤다.
6. **검색필터 화면을 캡처 없이 추정으로 먼저 만들었다**(R-12 위반). 맞긴 했지만 순서가 틀렸다.
7. **`systemctl restart` 를 `sudo` 없이 안내했다.** 사용자가 root 비밀번호 프롬프트를 만났다.
8. **브라우저 JS 캐시 때문에 옛 코드를 검증할 뻔했다.** `location.reload()` 로는 안 바뀐다.
   `typeof 함수`로 로드 여부를 먼저 확인하고, 안 바뀌었으면 파일을 직접 받아 평가했다.

9. **커밋 하나가 등록 실행부를 통째로 지웠다.** `8800c16`에서 `lstFillAttributes`를
   `lstBuildAttributes`로 바꾸면서 그 아래 178줄(`lstOpenSubmit`·`#lstSubGo`·`lstWatchQueue`)이
   같이 사라졌다. `index.html`의 모달 마크업은 남아서 화면은 멀쩡해 보였고, 그 뒤로
   **등록 버튼을 실제로 눌러본 사람이 없어** 다음 세션에서 사용자가 등록을 시도할 때까지
   드러나지 않았다(R-13의 사각지대 — "바꾼 화면"만 눌러보고 "바꾼 파일이 건드린 화면"은 안 눌렀다).
   함수 삭제는 문법 검사에 안 걸린다. **호출부는 남고 정의만 사라지면 조용하다.**

10. **제조사를 담을 자리가 없어서 남의 값이 등록됐다.** 첫 등록 실측: WING '상품 주요 정보'의
   제조사가 `루모아` — 카탈로그 매칭에서 본 **경쟁 상품의 제조사**였다. 카탈로그 화면의
   [이 정보 쓰기]가 `brand`·`manufacture`를 준비 건에 그대로 써넣고 있었고, 준비 건 화면
   어디에도 제조사 칸이 없어 사람이 고칠 수도 없었다. 확인 모달 요약에도 없어서 안 보였다.
   **1번(색상=감자색)과 완전히 같은 구조다** — 담을 자리가 없으면 남의 값이 흘러든다.
   → 카탈로그는 참고만, 제조사 칸 신설, 확인 모달 요약에 브랜드·제조사 추가,
   카탈로그 값과 같으면 등록 직전 경고.
