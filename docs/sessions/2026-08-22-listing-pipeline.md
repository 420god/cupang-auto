# S-2026-08-22 · 등록 파이프라인

> **언제 읽나**: 등록 화면을 고칠 때. "왜 이렇게 나눠져 있지?" 싶을 때.
> **최종 검증**: 2026-08-22 (10개 화면 전부 실제 DB 왕복 · 등록 실행은 큐 직전까지)
> **관련 코드**: `web/js/86~94-listing-*.js` · `db/migrations/031~038` ·
> `scripts/coupang-write-worker.js` · 상세는 `../domain/product-listing.md`

## 한 일

등록 모달 한 판을 **10개 화면 파이프라인**으로 쪼갰다(D-21).

```
소싱 즐겨찾기 → [등록 준비]
  ① 카테고리(+카탈로그 매칭) → ② 상품명·검색어 → ③ 옵션·가격 → ④ 검색필터
  → ⑤ 대표이미지 → ⑥ 상세페이지 → ⑦ 물류·바코드 → 상품등록에서 확인 후 발사
                                        등록 설정(기본값·양식)
```

마이그레이션 **031~038** 8개, 웹 파일 **86~94** 9개 신설, 워커에 `itemCommon` 병합 추가.

## 실물로 확정한 것 (추측이었다가 바뀐 것들)

| 무엇 | 결론 |
|---|---|
| `skuInfo` 항목 수 | 15개인 줄 알았는데 **22개**. 주면 전부 필수라 몰랐으면 등록이 깨졌다 |
| "상품 바코드가 없어요" | `originalBarcode: null` (상품 13건 전수). **자체 바코드 경로는 여전히 미검증** |
| 카테고리 코드 체계 | 소싱 수집용 = 등록용 `displayCategoryCode` (표본 1건) |
| 검색필터의 정체 | 카테고리 속성 중 `required !== 'MANDATORY'`. **캡처와 25개가 일치** |
| 드롭다운 값 | 우리가 이미 받아둔 메타에 있었다(`inputType` · `inputValues` · `usableUnits`) |
| 옵션명 | 필수속성의 조합 (`감자색 70g 1개`) |
| 카탈로그 매칭 | Open API 에 **없다**(등록 몸통 23키에 카탈로그 지정 필드 자체가 없음) → WING 내부 API |

## 틀린 것

1. **필수속성을 추측으로 채웠다.** 값을 담을 자리가 없어서 색상←옵션명, 무게←잰 값으로
   유추했는데, 실측에서 복제 원본의 `색상=감자색 · 개당 중량=70g`이 그대로 등록될 뻔했다.
   → 038로 자리를 만들자 추측이 사라졌다. **추측이 필요하다는 건 저장할 자리가 없다는 신호다.**
2. **카탈로그 매칭 파서가 `categoryId`(7359)를 등록 코드로 집었다.** 진짜는
   `displayCategoryInfo[0].leafCategoryCode`(103112). 그대로 뒀으면 엉뚱한 카테고리로 등록됐다.
3. **뼈대 완료 판정에 남긴 예외 하나가 규칙을 통째로 무력화했다**(035 → 036).
   `or 복제 원본 있음`을 뒀는데 뼈대를 붙일 때 복제 원본 ID도 같이 채워져서,
   한쪽만 붙여도 완료로 떴다.
4. **"결과 0건"과 "파싱 실패"를 같은 문구로 뭉갰다.** 사용자가 URL로 검색해 0건이 나왔는데
   화면은 "필드 이름이 예상과 다릅니다"라고 했다 — 사실이 아니었다(R-15 위반).
5. **URL을 그대로 API에 보냈다.** `keyword` 에는 상품번호만 넣어야 한다. WING 화면도
   URL 을 붙여넣으면 숫자만 뽑아 보낸다 — 첫 캡처에 이미 답이 있었는데 못 봤다.
6. **검색필터 화면을 캡처 없이 추정으로 먼저 만들었다**(R-12 위반). 맞긴 했지만 순서가 틀렸다.
7. **`systemctl restart` 를 `sudo` 없이 안내했다.** 사용자가 root 비밀번호 프롬프트를 만났다.
8. **브라우저 JS 캐시 때문에 옛 코드를 검증할 뻔했다.** `location.reload()` 로는 안 바뀐다.
   `typeof 함수`로 로드 여부를 먼저 확인하고, 안 바뀌었으면 파일을 직접 받아 평가했다.

## 열려 있는 것

- **첫 등록을 아직 안 해봤다.** 확인 모달까지만 검증했다(되돌릴 수 없는 일이라 사용자 몫)
- 미검증 3가지: 자체 바코드 경로 · 면세/성인전용/혼합구성 코드값 · 유통기한 필수 카테고리 분기
- `producedAtManaged` 와 `manufacturedAtManaged` 중 어느 쪽이 WING의 "제조일"인지 모름(13건 전부 false)
- 소싱 화면이 미완성이라 옵션·가격 값이 아직 소싱에서 안 넘어온다(`price_source='manual'`만 생김)
- 상품원장의 공급처·한글표시사항을 적절한 곳으로 옮기는 일(사용자 언급, 미착수)
