## 틀린 것 ← 다음 세션은 여기부터

**① 청구서 구조를 세 번 연속 잘못 가정했다**
매번 "이번엔 파악했다"고 생각했고 매번 새 형태가 나왔다(총금액이 첫 줄 → 한가운데 → 독립된 줄).
**교훈**: 같은 업체가 발행해도 줄 구조가 매번 다르다. 구조를 가정하지 말고 **검산에 기댄다**(R-14, D-10).

**② 문서에 적힌 API 필드명을 믿고 코드를 짰다**
`rocketGrowthItem` vs 실제 `rocketGrowthItemData`. 2026-08-17에 문서를 틀리게 적었고 코드가
그대로 따랐다. **`--products` 크론이 매일 돌면서 모든 옵션을 버리고 0행을 넣고 있었다**
(`upsert 0행`은 에러가 안 난다). 실물 응답을 한 번도 저장 안 해봐서 아무도 몰랐다.
**교훈**: 실물을 확인한 뒤 코드를 쓴다(R-12). "조회 N건 → 저장 0행"을 조용히 넘기지 않는다.

**③ PDF 추출기가 공백을 버리는 걸 몰랐다**
`pdf-parse` 기본 추출이 `세알 20 6 9.8` → `세알2069.8`로 붙여버렸다. 파서 문제로 오인.
pypdf로는 멀쩡했다 — **PDF엔 정보가 다 있었다.**
**교훈**: 라이브러리마다 결과가 다르다. 한쪽에서 됐다고 다른 쪽도 되리라 가정하지 않는다(D-14).

**④ 로트 창고수량에 발주수량을 미리 넣어뒀다**
아직 도착도 안 했는데 창고에 있는 것처럼 기록돼서, 출고 화면이 발주 단계로 우회 판정을 해야 했다.
부분 도착이 실제로 있다는 걸 뒤늦게 확인하고 020으로 바로잡았다.
**교훈**: 실무를 먼저 캐물었으면 처음부터 안 틀렸다(R-10).

**⑤ 배송비 재배분을 안 하기로 했다가 뒤집었다**
"이미 확정된 원가를 바꾸면 과거 이익이 흔들린다"고 제안했는데, 사용자가 "같은 판매자 물건이
남아 있으면 배송비는 그쪽이 나눠 진다"고 정정. **취소는 출고 전에 일어나므로 원가를 고쳐도
과거가 안 흔들린다** — 내 전제가 틀렸다.

**⑥ 파생 화면이 원본 부재를 말해주지 않았다**
입고 화면이 로트만 보여주는데 SKU 미연결이면 로트가 없어서, 사용자가 "아무것도 안 나온다"를
겪고도 원인을 못 찾았다. **"없음"은 "0개"와 "애초에 안 만들어짐"을 구분 못 한다**(R-15).

**⑦ "애매하면 물어본다" 규칙을 잘 안 지켰다**
사용자 지적. 원인 셋 — 규칙이 문서 끝에 있었고, "애매하면"이 추상적이었고, **질문이 진행을 막았다.**
위치를 맨 앞으로, 추상을 트리거 6종으로, **질문에 항상 제안을 붙여** 비용을 없앴다(R-10).
