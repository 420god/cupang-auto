# 문서 작성 규칙

> **언제 읽나**: 문서를 새로 만들거나 고칠 때, `[세션 마무리!]`를 할 때.
> **최종 갱신**: 2026-08-19

## 왜 이렇게 하나

세션이 계속 바뀐다. 다음 세션은 **코드 + 이 문서들만으로** 지금까지의 맥락을 이해할 수 있어야 한다.
동시에 문서를 읽는 것 자체가 토큰이다. 그래서 **두 층으로 나눈다.**

```
자동 주입 (고를 수 없는 비용)      찾아 읽기 (안 열면 0원)
─────────────────────────       ────────────────────────
CLAUDE.md          6,000자      docs/**  깊이 제한 없음
web/CLAUDE.md      3,000자
db/CLAUDE.md       2,000자
extension/CLAUDE.md 2,000자
STATUS.md          (짧게)
```

**`CLAUDE.md`는 "모르고 건드리면 사고 나는 것"만.** 서사·계산식·경위는 전부 `docs/`로 간다.
한도를 넘으면 늘리지 말고 **내려보낸다**(R-17).

## 모든 문서 맨 위 세 줄

```markdown
> **언제 읽나**: (이 문서를 열어야 하는 상황)
> **최종 검증**: 2026-08-19 (무엇으로 검증했는지)
> **관련 코드**: web/app.js loadLotCogs() · db/migrations/016,019,020
```

**"언제 읽나"가 가장 중요하다.** 인덱스에서 이 한 줄만 보고 **열지 말지 판단**할 수 있으면 토큰이 크게 절약된다.

## 사실은 한 곳에만

같은 사실을 두 문서에 쓰지 않는다. 한 곳에 쓰고 나머지는 **링크**한다.
두 곳에 있으면 반드시 한쪽이 낡는다 — 그리고 어느 쪽이 맞는지 알 수 없게 된다.

## 덧붙이지 말고 교체한다

내용이 바뀌면 **아래에 새로 쓰지 말고 기존 문단을 고친다.**
날짜순으로 쌓으면 같은 주제가 흩어지고, 어느 것이 최신인지 매번 확인해야 한다.

폐기된 결정은 본문에서 지우고, 필요하면 한 줄만 남긴다.
```
~~예전 방식~~ 이 아니라:
> 2026-08-19 폐기: 위치로 풀려다 세 번 실패 → 산수 방식으로 대체. 경위는 D-14
```

## 참조는 ID로 한다

날짜 참조(`docs/decisions.md 2026-08-18`)는 문서를 재구성하면 깨진다.
그래서 **재구성이 두려워지고, 두려우니 덧붙이게 된다.** 악순환.

```js
/* 바코드를 SKU 키로 쓰는 이유 → D-02 */
/* 규칙: 실물 확인 후 코딩 → R-12 */
```

- `D-NN` 결정 → `docs/decisions/INDEX.md`
- `R-NN` 규칙 → `docs/rules/INDEX.md`
- `S-YYYY-MM-DD` 세션 → `docs/sessions/`

## 검증한 것만 "확정"이라 쓴다

숫자를 적을 때는 **어떻게 검증했는지 같이** 쓴다.
```
역산 환율 320.00 (2055.28 CNY × 320 = 657,690원 = 청구서 기재액과 일치)
```
검증 안 한 건 "미검증"이라고 명시한다. 나중에 그 값을 믿고 쌓아 올리면 조용히 틀린다.

## 실패도 남긴다

**틀린 시도를 지우면 다음 세션이 같은 함정에 다시 빠진다.**
"막다른 길로 확인됨" 항목은 특히 중요하다 — 이미 조사해서 불가능으로 결론난 것을
다시 파는 데 세션 하나를 통째로 쓸 수 있다.

## `[세션 마무리!]` 절차

사용자가 이 말을 하면 아래를 순서대로 한다.

### 1. 주제 문서 갱신
이번 세션에 바뀐 내용을 **해당 주제 문서에 반영**한다(덧붙이기 아니라 교체).
새 주제가 생겼으면 문서를 만들고 `docs/INDEX.md`에 등록한다.

### 2. 결정 등록
새로 확정된 결정 중 아래에 해당하면 `docs/decisions/INDEX.md`에 ID를 부여한다.
1. 뒤집으면 비용이 큰 것
2. 이미 막다른 길로 판명난 것
3. 여러 문서·코드에서 반복 참조되는 것
4. 사업 규칙으로 합의한 것

해당 없으면 주제 문서 본문에만 남기고 ID를 붙이지 않는다 — **모든 것에 ID를 붙이면 목록이 소음이 된다.**

### 3. 규칙 회고 (4문항)
```
1. 헛수고·재작업이 있었나?   → 원인이 규칙 부재면 후보 추가
2. 기존 규칙을 어겼나?       → 위반 +1, 왜 안 지켜졌는지 한 줄
3. 규칙이 사고를 막았나?     → 발동 +1
4. 오래 아무 일 없던 규칙?   → 강등 후보로 표시
```
상한(전역 5·습관 8·폴더별 4)을 넘으면 **가장 약한 것을 내린다.**

### 4. 세션 로그 작성
`docs/sessions/YYYY-MM-DD-주제.md` — **요약형**. 한 일 · 결정 · **틀린 것** · 열려 있는 것 · 다음 세션이 먼저 읽을 것.
**틀린 것을 남기는 게 핵심이다.** 결론만 남기면 다음 세션이 같은 함정에 빠진다.
`docs/sessions/INDEX.md`에 한 줄 추가한다.

### 5. STATUS.md 갱신
마이그레이션 실행 상태 · 배포 · 미해결 목록.

### 6. 점검
```bash
bash scripts/check_docs.sh
```
크기 한도 초과 · 머리글 누락 · INDEX 미등록 · 깨진 ID 참조를 잡는다.

### 7. 커밋 · 푸시
`main`에 커밋하고 푸시한다.
