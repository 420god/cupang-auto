# 쿠플러스 (구매대행)

> **언제 읽나**: 발주 프로세스·환율·서류를 다룰 때. 청구서 인식은 `domain/invoice-parsing.md`.
> **최종 검증**: 2026-08-22 (구매요청 폼 캡처 5장) · 2026-08-19 (청구서 5종 + 공지 팝업)
> **관련 코드**: `web/js/50-purchase.js`·`60-inbound.js`·`70-outbound.js` · `db/migrations/016`

## 사업 구조 — 코드로는 알 수 없는 전제

```
중국 1688 사입 → 쿠플러스(㈜쿠패스) 구매대행 → 통합통관 → 배대지 창고 작업
→ 한국 입고 → 로켓그로스
```

다품종 소량. 6개월 내 SKU 수천 개 목표. 판매자배송·타채널은 "나중에 할 수도 있다" 전제만.

## 프로세스

```
구매요청(쿠플러스 웹)  바코드 입력 → 상품매칭 → 구매링크 → 중국어 옵션 선택
                       → [요청등록] 모달(수량·도착지·검수/포장·한글표시사항·요청사항)
  → 구매대행 청구서 PDF (카톡)
  → 입금 (건별 또는 예치금 차감, 둘 다 씀)
  → 1688 발주        ← 재고없음 취소 발생 시 쿠플러스가 카톡으로 물어봄
  → 중국 배대지 도착 (카톡 통보)
  → 한국 입고요청 (카톡)
  → 작업비 청구서 (엑셀, 후불)
  → 쿠팡센터 납품
```

**쿠플러스의 `판매/분석`·`해외물류` 탭은 미사용** — 참조하지 말 것.
**중국 창고 재고는 쿠플러스 화면에서 볼 수 없다** — 우리가 직접 센다.

## 구매요청 폼 (2026-08-22 캡처로 확정)

**요청 1건 = SKU 1개**(옵션 하나). 여러 SKU를 사려면 줄을 여러 개 만든다.
청구서(`purchase_orders`)는 **여러 요청을 묶어 한 장**으로 오므로 단위가 다르다.

### 목록 화면 — 탭 `구매요청` / `구매요청내역`

| 컬럼 | 무엇 | 우리 쪽 값 |
|---|---|---|
| 제품정보 | 바코드·제품명 | `my_skus.barcode` · `sku_name` |
| 상품매칭 | [매칭필요] 배지 → 쿠팡 상품과 잇는 단계 | — |
| 구매링크 | [구매링크] 버튼 | `sku_suppliers.offer_url` |
| 옵션1_중국어 · 옵션2_중국어 | 돋보기로 1688 옵션에서 고른다 | `sku_suppliers.option1_cn` · `option2_cn` |
| 구매재고 | 1688 재고 | — (주문 전엔 못 믿는다) |
| 요청사항 | [요청등록] → 모달 | 아래 |
| 구매요청수량 | | 우리가 정한다 |
| Actions | 복사 · 수정 · 보기 · 삭제 | — |

줄을 새로 만들 때 **"바코드 번호 (없으면 생략)"** 로 시작한다 —
바코드 없이도 넣을 수 있고, 그때 제품정보에 `NOBARCODE` 로 뜬다(샘플 직수령 건).

### [요청등록] 모달

```
1. 구매요청수량      ← 옆에 "최소주문:2개 / 재고:0개" 를 쿠플러스가 보여준다
2. 판매구성수량      기본 1. 세트로 팔면 여기가 커진다(sku_bom 과 같은 개념)
3. A-B번들 묶음구성여부   토글 '묶음구성'
4. 도착지            [쿠팡센터] | [화주]   ← 기본 쿠팡센터. 화주 = 샘플 직수령
   …                 5~7 은 아직 캡처가 없다
8. 검수 및 포장
9. (한글표시사항으로 추정 — 미확인)
```

**우리 화면**: `구매요청`(공급) — 묶음 아래 SKU 줄을 쌓고 칸마다 복사 버튼을 둔다.
모달의 항목 순서를 위 폼과 **똑같이** 맞췄다. 순서가 다르면 옮겨 적을 때 눈이 미끄러진다.

담는 곳이 두 갈래다. **신규 상품은 SKU 목록에 없다** — 바코드가 쿠팡 발급이라
등록·동기화 뒤에야 `my_skus` 행이 생기는데, 첫 물량은 그전에 사야 한다.

| 갈래 | 출처 | 권장 수량 |
|---|---|---|
| 재발주 | `my_skus` + 재고 계산 | 있다(일평균·리드타임·가진 물량·MOQ) |
| **신규(첫 구매)** | `listing_project_items`(등록 준비) | **없다** — 판매 이력이 없다. 지어내지 않는다 |

신규로 담은 줄은 `sku_id`·`barcode_text` 가 비어 있다. 쿠플러스 폼도 "바코드 번호
(없으면 생략)"을 허용하므로 그대로 넣을 수 있다. 나중에 바코드가 나와도
**자동으로 이어지지는 않는다**(미해결).

**요청 ↔ 청구서**: 발주 상세에서 묶음을 고르면 수량을 대조한다. SKU로 먼저 맞추고
없으면 바코드로 맞춘다. 못 맞춘 줄은 "못 맞춤"으로 남긴다 — 조용히 빼면 수량이
맞는 것처럼 보인다.

**자동화는 아직 안 했다**(사용자 요구 2026-08-22). 확장프로그램이 이 폼을 직접
채우게 하려면 쿠플러스 도메인·폼 DOM이 필요하고, **어디까지 자동으로 할지**를 정해야
한다 — 2026-08-18 결정은 "초안 생성 → 사람이 확인 후 실행, 완전 자동은 기각(돈이
나가는 행위)"이었다. 그 결정을 바꾸는 것인지 확인이 필요하다.

**MOQ와 1688 재고를 쿠플러스가 화면에서 알려준다.** `my_skus.moq_source='couplus'` 가
이걸 가리킨다.

#### 8. 검수 및 포장

포장 방법(**라디오, 하나만**):

| 값 | 비고 |
|---|---|
| **포장 방법 위임** | **기본값** |
| 재포장 생략 | |
| 투명 OPP 봉투 포장 | 무료 |
| 불투명 LDPE 봉투 포장 | 무료 |

추가 작업(**토글, 여러 개**):

| 값 | 비용 | 기본 |
|---|---|---|
| 기본검수/분류/포장/포장자재 | ₩200 | **켜짐** |
| 바코드라벨 (Made in China·한글표시사항 기본포함) | ₩100 | **켜짐** |
| 중국어 마스킹 | 무료 | 꺼짐 |
| 에어캡 포장 | 실비 | 꺼짐 |
| 원산지라벨 봉제 | 6,000원/시간 | 꺼짐 — **의류 수입 시 필수** |
| 원산지 도장 | 6,000원/시간 | 꺼짐 — **신발류는 봉제 또는 도장 필수** |
| 원산지 택(태그) | 6,000원/시간 | 꺼짐 — **가방류는 봉제 또는 택 필수** |

**개당 300원의 출처가 여기다** — 기본검수 200 + 바코드라벨 100. 제트 청구서에서
`89,400÷447=200`, `89,400÷894=100` 으로 역산했던 숫자와 폼의 표시가 일치한다.
시간당 6,000원짜리 작업이 붙으면 그 공식이 깨진다 → `extra_fee` 를 열어둔 이유.

### 한글표시사항 — 10개 항목

```
바코드 번호 · 제품명 · 수입원/판매원 · 제조원 · 제조국 · 내용량
· 원료명및성분명(재질) · 상품유형 · 사용시주의사항 · 사용기준
```

앞의 둘은 이미 `my_skus.barcode` · `sku_name` 이고, 나머지 8개가 `label_*` 컬럼이다.
**전에 이 문서가 "9필드"라고 적은 것은 틀렸다** — 모달의 섹션 번호를 개수로 옮긴
것으로 보인다. 캡처를 결론만 남기고 버리면 이런 게 조용히 굳는다(R-12).

## 환율 — 두 개고, 주문 시각에 고정된다

| 용도 | 값(2026-08) | 성격 |
|---|---|---|
| 구매대행 | 320 → **310**(08-05부터) | 상품가+중국내배송+국제운임(LCL)+통관+대행수수료 **전부 포함** |
| 작업비 정산 | 219.72 | 실환율에 가깝다 |

공지 원문: "8월 4일 중국시간 오후 5시까지 요청된 주문건은 320, 이후 생성된 주문건부터 310 자동 적용."
→ **로트마다 저장한다**(D-03). 사이트 공지 팝업으로만 통보되므로 바뀐 걸 놓치기 쉽다.

세트구성·특수요청이 붙으면 유동이라 `extra_fee`로 열어뒀다.

## 바코드

쿠팡이 발급 → 로켓그로스 입고용과 **동일** → 쿠플러스 구매요청에 입력 → **구매대행 청구서에
그대로 찍혀 나옴** → 배대지가 물리적으로 부착.
발주·청구서·창고·쿠팡이 전부 같은 번호를 쓰는 유일한 값이라 조인키로 쓴다 → D-02

**순서 제약**: `쿠팡 상품등록 → 로켓그로스 등록 → 바코드 발급 → 쿠플러스 입력 → 발주`.
다만 **상품 등록 전에 먼저 발주하는 경우도 있다** — 그때는 바코드 없이 나가고, 물건이 중국에
도착한 뒤 상품을 등록해 바코드를 받아 바코드 작업을 한다 → D-05

## 예치금

불량·취소 환불이 예치금으로 들어온다. **잔액은 사진으로만 통보** → 수기 입력 + 계산값과 대사.
결제는 건별 입금과 예치금 차감을 **둘 다** 쓴다.

## 그 밖의 확인된 사실

- **MOQ**는 SKU마다 다르고 같은 상품도 판매자마다 다르다. 쿠플러스가 1688에서 긁어오지만 수기 수정 가능해야 한다
- **1688 재고는 주문 전엔 알 수 없다** — "재고없음 취소"가 실제로 발생한다
- **세트/묶음**은 중국에서 낱개로 사서 배대지에서 묶어 포장한다. 묶음 하나에 바코드 하나
- **한글표시사항 10항목**(그중 8개가 `label_*`)은 SKU마다 고정값이라 저장해두고 재발주 시 자동으로 채운다
- **국제배송은 해상** 위주. 발주부터 입고까지 대략 2주(SKU마다 다름 → 실측으로 튜닝)
